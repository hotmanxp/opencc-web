## 0. 范围澄清

`REPL.tsx` 把"**运行时 session 逻辑**"和"**Ink UI 渲染**"混在同一个组件里。in-process REPL(`createReplSession` + `ReplRuntime`)只承担前者,后者交给 zai-web 的 React 渲染层走 SSE 消费 `runtime.*`。本文对比的核心是"**运行时 session 逻辑**"的 1:1 对标;UI-only 的 hooks 在第 6 节单独列出,它们本来就不属于 in-process REPL 的职责。

## 1. TL;DR

| 维度 | 覆盖度 |
|---|---|
| **核心生命周期**(submit / enqueue / interrupt / dispose / getState / whenHydrated) | **100%** |
| **并发保护**(QueryGuard) | **100%** |
| **真实 query() 路径**(vendor SDK + sdkEventAdapter + ToolUseContext 完整填充) | **100%** |
| **L1 外部世界 polling adapter**(inbox / mailbox / skills / cron / commandQueue) | **~90%**(`useTaskListWatcher` 缺,proactive/swarm/backgrounding 是 P1 placeholder) |
| **L2 内部状态通知 adapter**(apiKey / costSummary / tasksV2 / notifications bus) | **~40%**(bus 完整,4 个 adapter 是 placeholder,真实 vendor 源未接) |
| **MCP / IDE / Plugin / FileHistory / 上下文折叠** | **缺**(本应走 host opts 注入,部分未实现) |
| **Slash command 路由** | **~10%**(只 stub 3 个,真实 vendor commands 未接) |
| **30+ use*Notification UI-only 钩子** | **缺**(UI-only,不在 session 层职责) |
| **所有 UI-only hooks**(键位 / scroll / transcript / fullscreen / suspend-resume) | **缺**(UI-only,不在 session 层职责) |
| **Auto-restore on user-cancel** | **缺**(TUI 有完整 `restoreMessageSyncRef` 路径) |
| **Events → SSE `runtime.*` 映射** | **100%** |

实际剩余 gap 按工作量分三档:
- **小**(1-2 天):`useTaskListWatcher` adapter、auto-restore on cancel、model fallback 走 migration 路径
- **中**(3-5 天):4 个 L2 adapter 接真实 vendor 源(`getAccessToken` / `useCostSummary` / `useTasksV2` / `useApiKeyVerification`)、`useSwarmInitialization` 的 status/exit hooks、`useProactive` tick source
- **大**(5+ 天):slash command 路由接真实 vendor commands 表(从 `KNOWN_SLASH_COMMANDS = 3` 扩到 vendor 全量)、context collapse、IDE/MCP/Plugin 的 `ToolUseContext` 完整覆盖

## 2. 核心生命周期(完全对标 ✅)

| TUI 入口 | TUI 位置 | in-process 入口 | in-process 位置 |
|---|---|---|---|
| `onSubmit(input, helpers, …)` | `REPL.tsx:3432` | `session.submit(content)` | `createReplSession.ts:588` |
| `executeQueuedInput` / `useQueueProcessor` | `REPL.tsx:4242` | `session.enqueue(content, priority)` + `setupCommandQueue` | `createReplSession.ts:606` / `setupCommandQueue.ts:96` |
| `queryGuard.tryStart()` concurrent guard | `REPL.tsx:3123` | `setupQueryGuard` 包装 vendor `QueryGuard` | `setupQueryGuard.ts:22` |
| `onQuery → onQueryImpl → query()` 真实流 | `REPL.tsx:3047-3057` | `createReplSession.runTurn` → vendor `query({ querySource: 'server-repl' })` | `createReplSession.ts:537-550` |
| `stateMachines`(OnSubmit/OnQuery/OnQueryImpl class 化) | — | `OnSubmitStateMachine` / `OnQueryStateMachine` / `OnQueryImplStateMachine` | `stateMachines.ts` |
| `interrupt`/`forceEnd` 路径 | `REPL.tsx:3282-3312` | `session.interrupt(reason)`(graceful,不抛错) | `createReplSession.ts:622-648` |
| `restoreSession` / rewind + compact boundary | `REPL.tsx:2847-2860` | `restoreSession` + `whenHydrated()` 契约 | `sessionRestore.ts` + `createReplSession.ts:312-332, 664-666` |
| `dispose` / LIFO teardown | `REPL.tsx` 顶部 useEffect cleanup | `session.dispose()` + LIFO stack | `createReplSession.ts:343-357, 683-700` |

要点:
- `setupCommandQueue` 复用 vendor `messageQueueManager` 模块,`useCommandQueue` 与 in-process adapter **共享 module-level state** —— 这是 TUI 队列与 in-process 队列语义一致的关键。
- `setupQueryGuard` 是 vendor `QueryGuard` 类的薄包装,保留 generation token 语义。并发时 `tryStart()` 返回 null → `runTurn` 走 `cmdQueue.enqueue` 路径,而不是嵌套。
- `OnQueryStateMachine` 在 P1 是 placeholder,P3 真接 vendor `query()`,`onSubmit.onQuery` 也由 `runTurn` 直接驱动。
- LIFO teardown 顺序硬编码在 `createReplSession.ts:343-357`,与 brief 约定的 brief 顺序一致:cmdQueue → cron → proactive → inbox → mailbox → swarm → background → skills → apiKey → cost → tasksV2 → notif → guard。所有 4 个 P2 teardown 都幂等,`dispose()` 可重复调用。

## 5. ToolUseContext 完整覆盖(P3-T0 fix)

P3-T0 之前 `runTurn` 传给 vendor `query()` 的 `toolUseContext` 是 `{} as any`,vendor `claude.ts` 同步读取 `options.tools / commands / mcpClients / mainLoopModel / abortController / readFileState / getAppState`,所以 LLM 完全看不到任何工具,turn 等于纯文本对话。

P3-T0 fix(`createReplSession.ts:434-536`)后:
- `fallbackTools` = `opts.tools ?? vendor.getTools(EmptyToolPermissionContext)` —— `EmptyToolPermissionContext` 让 permission 规则不 filter,host-supplied tools 已经过 host 端过滤
- `fallbackCommands` = `opts.commands ?? await vendor.getCommands(cwd)`
- `fallbackMcpClients` = `opts.mcpClients ?? []`
- `fallbackReadFileState` = `opts.readFileState ?? vendor.createFileStateCacheWithSizeLimit(100)`
- `fallbackAgents` = `opts.agents ?? []`
- `getAppState()` 加防御性默认值(`toolPermissionContext: { mode: 'default', additionalWorkingDirectories: new Map(), prePlanMode: 'default' }`),避免 host 传最小 `getAppState` 时 vendor dereference undefined panic
- `NODE_ENV !== 'test'` 才走 vendor 懒加载,避免 vitest mock `query.js` 时连带拉入 `tools.js → BashTool → prompt.ts` 求值链;`ZAI_P3_T0_FORCE_VENDOR_FALLBACK='1'` 显式 opt-in 走真 vendor graph
- `querySource: 'server-repl'` 字面量让 vendor 区分 in-process server session vs `repl_main_thread`(终端 REPL)vs `sdk`(CLI 子进程)

测试 seam `__test_emitReplEvent` 仅在 `NODE_ENV === 'test'` 时暴露,生产构建带不到。

## 6. UI-only hooks(in-process 永远不会有,留给 zai-web)

下列**不是** UI-only,属于 session 逻辑但 in-process 还没接或只接了 stub:

### 7.2 Slash command 路由

TUI:onSubmit 里 `input.trim().startsWith('/')` → 走 `handlePromptSubmit` → 实际命令处理由 vendor commands 表(`/help`, `/compact`, `/config`, `/clear`, `/model`, `/mcp`, `/agents`, `/bug`, `/init`, `/pr-comments` 等)。

in-process(`agentRuntime.repl.ts:81-118`):`ReplRuntime.query()` 先调 `parseSlashCommand`(`setupCommandQueue.ts:33`),命中 `KNOWN_SLASH_COMMANDS = ['loop', 'swarm', 'send']` 就 yield `runtime.notification: { kind: '<cmd>-scheduled' }` + `runtime.done`;未命中 yield `kind: 'unknown-command'`。

⚠️ **只 stub 了 3 个命令**,其他真实 vendor commands 没有路由,会当 unknown-command emit。当前并不调 vendor `handlePromptSubmit`,没有 local-jsx 区分(`matchingCommand.type === 'local-jsx'`),没有 keybinding 触发 immediate 路径,没有 history 写入(`addToHistory`)。

### 7.3 Auto-restore on user-cancel

TUI `REPL.tsx:3300-3312` 有完整 auto-restore:user 中断且没产生有意义的响应时,自动 rewind 到上一条 user message 并把 prompt 装回输入框。in-process 没有这条路径 —— `interrupt()` 只发 `runtime.aborted` 事件,host 端不会自动 rewind。

### 7.4 Model fallback / migration

TUI `useModelMigrationNotifications` 监听模型自动迁移。in-process `runTurn` 直接传 `(opts as any).model ?? 'claude-sonnet-4-5'`,没走 migration 流程。

### 7.5 Swarm 完整生命周期

TUI `onQuery` 里有 `setMemberActive(teamName, agentName, true)`(`REPL.tsx:3111-3118`),teammate status / exit hook 都有。in-process `setupSwarmInitialization` 只实现了 `createTeammate`,teammate 状态机没接。

## 8. 错误 / 中断 / 终态语义

| 路径 | TUI | in-process |
|---|---|---|
| user-cancel + 空输入 + queue 空 | 自动 restore 上一条 user message(`restoreMessageSyncRef.current(lastUserMsg)`) | ❌ |
| 显式 interrupt | `setAbortController` + `queryGuard.forceEnd()` | `session.interrupt(reason)` 调 `onQuery.signalInterrupt` + emit `turnEnd` + 走 enqueueEvent `runtime.aborted` |
| 抛错 | `onQueryImpl` throw → `resetLoadingState` + `setLastQueryCompletionTime` | `runTurn` catch → emit `sessionCrash` → ReplRuntime 包装 `runtime.error`;但 **runTurn 自身会 rethrow**(`throw err` after emit),`submit()` 的 `await` 会 reject |
| session dispose 之后 submit | TUI React 不挂载了 | `submit()` 抛 `createReplSession ${sid}: disposed` |
| `turnIndex` 计数 | TUI 隐式按 React render | `createReplSession` 自维护 `let turnIndex` + `turnIndex += 1` at start of runTurn |
| 防御性 hydrate guard(dispose race) | N/A | ✅ `if (isDisposed) return` 在 `restorePromise.then` 里有 |

`runTurn` 在 `finally` 块保证 `isRunning = false` + `guard.state.end(gen)`,即使 vendor `query()` 抛错也清理,不会卡住下一次 submit。

## 9. ReplEvent → SSE `runtime.*` 事件映射

`ReplRuntime.getOrCreate` 里 `hooks.onEvent`(`agentRuntime.repl.ts:307-369`):

| ReplEvent | runtime.* 事件 | 备注 |
|---|---|---|
| `turnEnd` | `runtime.done` | ✅ |
| `sessionCrash` | `runtime.error` | ✅ |
| `notification` | 透传 | ✅ |
| `runtime`(wrapper, payload = RuntimeEvent) | 解包 payload,透传 | ✅ P3-T0 fix |
| `turnStart` / `sessionStart` / `sessionEnd` | **丢弃**(在 `query()` 外层 yield wrapper) | ✅ |

`turnIndex` 在 ReplEvent 上由 `createReplSession` 自维护(`turnIndex += 1` at runTurn start),runtime wrapper event 上继承 `inner.turnIndex ?? replEvent.turnIndex`,保证 host SSE 消费时单调递增且与 turn 边界对齐。

## 10. 后续工作建议

按工作量分三档:

**小(1-2 天)**:
- `useTaskListWatcher` adapter(ant-only,工作模式类似 `useInboxPoller` —— 轮询 task list 变化)
- `auto-restore on cancel`(在 `interrupt()` 后通过 `restoreSession` 取最后一条 user message 并通过 `notification` ReplEvent 通知 host)
- model fallback 走 migration 路径(从 `useModelMigrationNotifications` 抽 `getCurrentEffectiveModel`)

**中(3-5 天)**:
- 4 个 L2 adapter 接真实 vendor 源:`getAccessToken` 替代 env var 读、`useCostSummary` 真实 cost tracking、`useTasksV2` 内部逻辑、`useApiKeyVerification` 真实失败重试
- `useSwarmInitialization` 补 status updates / exit hooks / `setMemberActive`
- `useProactive` tick source(替换 `opts.onSubmitTick?.('')` placeholder)
- `setupSessionBackgrounding` 补真 backgrounding 路径(把 AbortController 注入 vendor `query()` 循环)

**大(5+ 天)**:
- slash command 路由接真实 vendor commands 表(从 `KNOWN_SLASH_COMMANDS = 3` 扩到 vendor 全量),需要:
  - 把 vendor `commands.ts` 的 `getCommands` 真正接进 `setupCommandQueue` / `ReplRuntime`
  - 实现 `matchingCommand.type === 'local-jsx'` 分支(`/help` `/config` `/mcp` 等)
  - 实现 keybinding 触发 immediate 路径
  - 实现 `addToHistory` 调用
- context collapse(从 `useProactive` 抽 `resetContextCollapse` 接到 `restoreMessageSync`)
- IDE/MCP/Plugin 的 `ToolUseContext` 完整覆盖(目前是 host 走 opts 注入,但 host 端 `agentRuntime.ts` 的具体路径还没确认)
