The Task 4.5 part 2 blocker ("full chat blocked on vendor stream→MessageParam translation") had two distinct root causes that were diagnosed and fixed independently. (1) **SDK hang** at `await client.messages.create(...)` in zai-server's dev runtime (Express + Vite + Bun-direct, all in one process) — same call from a standalone `bun -e` script against the same proxy returns 15 events in ~1.7s. The hang was inside the SDK's APIPromise chain (`messages.create → parseResponse → Stream.fromSSEResponse`) which constructs the stream object synchronously but never drives the underlying SSE reader. Fix: bypass `Anthropic#messages.create(...)` and drive the Anthropic SSE format directly with raw `fetch` — a tiny parser (~30 lines) in `fetchAnthropicStream` + `readSseAsAnthropicEvents`. Wire format is unchanged. While in there, also handled the secondary "input json is empty" 2013 from the MiniMax proxy on vendor-built tools that declare `inputSchema` as `ZodUnknown()` / `ZodAny()` / no schema — `zodToJsonSchema` emits the bare envelope `{"$schema": "..."}` with no `type: "object"` and no `properties`, which the proxy rejects. New `normalizeToolSchema` replaces any non-object / missing-schema output with `{"type": "object", "additionalProperties": true}` so the model still sees the tool's name + description. 6/6 normalizeToolSchema tests pass. Engine deps fallback path (for callers that don't pass `options.callModel`) remains intact — they still get the vendored `Message` shape as before.
